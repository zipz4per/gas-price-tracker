Archive a resolved bug in `openspec/bugs/`.

**This file is hand-written and is NOT generated by `openspec update`.** Its
siblings under `.claude/skills/openspec-*` are generated and will be rewritten
on a CLI upgrade; this one will not. See *Why this exists* at the bottom.

**Input**: a bug name after `/opsx:archive-bug` (e.g.
`/opsx:archive-bug doe-fuel-type-not-recognised`). If omitted, infer it from
conversation context; auto-select if exactly one unarchived bug exists;
otherwise list `openspec/bugs/*/` and ask.

The OpenSpec CLI does not know this record exists. **Never run
`openspec status`, `openspec instructions`, or `openspec archive` in this
workflow** — they resolve only against `openspec/changes/` and will report the
bug as not found. Every check below reads files directly.

**Steps**

1. **Resolve the bug**

   ```bash
   ls -d openspec/bugs/*/ | grep -v '/archive/$'
   ```

   The selected name must have `openspec/bugs/<name>/report.md`. If it does
   not, stop and say so — do not fall through to the change workflow, and do
   not create the file.

   Announce: "Using bug: <name>" and how to override
   (`/opsx:archive-bug <other>`).

   Read `openspec/bugs/<name>/report.md` in full. Every gate below is a
   judgement about its content, not a regex over it — read the sections and
   decide, rather than pattern-matching the pending markers alone.

2. **Gate: is the bug resolved?**

   A bug archives when it has *ended*, which is not the same as being fixed.
   Read `## Fixed by`. It must name one of:

   - a commit, as `<sha>  <subject>`
   - the change that carried the fix
   - `won't fix — <reason>`

   Still `_Pending._` means the bug has not ended. Warn, show the section, and
   ask the user to confirm before continuing.

   *Not a bug* is also a valid ending; it is recorded in `Fixed by` the same
   way `won't fix` is.

3. **Gate: is the decision recorded?**

   Read `## Does this need a change?`. Still `_Not yet decided._` means the
   most load-bearing question in the report was never answered — this is the
   section that says whether the fix altered what the system promises. Warn and
   confirm.

   A bug closed as *won't fix* or *not a bug* still answers it, usually **No**.

4. **Gate: has the blocking change archived?**

   This is the gate with no analogue in the change workflow, and the reason
   this skill exists rather than a bare `mv`.

   If `## Does this need a change?` begins **Yes** and names a change, that
   change must already be archived:

   ```bash
   ls -d openspec/changes/archive/*-<change-name>/ 2>/dev/null
   ```

   If the directory is absent, the fix has not landed in the specs yet. **A bug
   stays open until its change archives** — six months on, the search is for the
   symptom, not for the change that fixed it, so closing the bug early loses the
   trail. Warn, name the change that is still active, and confirm.

   If the answer is **No**, there is nothing to wait on.

5. **Gate: are the fix tasks done?**

   Count `- [ ]` against `- [x]` under `## Fix tasks` only — not across the
   whole file, since `## Root cause` may quote code containing brackets.

   `_None._`, or `_None — tracked in <change>._`, is complete: a bug whose fix
   lives in a change tracks its tasks there, and step 4 is what covers it.

   Incomplete boxes: warn with the count and confirm.

6. **Report the remaining pending markers**

   Any `_Not yet investigated._` or `_Pending._` still standing in
   `## Root cause`, `## Caused by`, or `## What the fix changed` is worth
   naming before the record freezes, because after the move nobody looks again.

   This is information, not a gate. A *won't fix* bug legitimately never gets a
   root cause, and saying so is a better record than a guess.

7. **Perform the archive**

   ```bash
   mkdir -p openspec/bugs/archive
   ```

   Target name: use the bug name as-is when it already starts with a
   `YYYY-MM-DD-` prefix; otherwise prepend today's date as
   `YYYY-MM-DD-<name>`. Never stack a second date. This is the same rule
   `openspec archive` uses for changes, and the same one
   `scripts/sync-project-board.py` strips when it reads the archive back.

   **If the target already exists, fail** — do not merge, overwrite, or pick a
   different date on the user's behalf. Report the collision and offer to
   rename the existing archive, delete it if it is a duplicate, or wait a day.

   ```bash
   mv "openspec/bugs/<name>" "openspec/bugs/archive/<target-name>"
   ```

   `.openspec.yaml` moves with the directory. The sync reads `capability:` and
   `layer:` from it after the move, so it must not be left behind.

8. **Display summary, and say what is left to do**

   The move does not touch the board. `scripts/sync-project-board.py` is what
   turns an archived bug into a **Done** card and closes its issue, and it has
   not run yet.

**Output On Success**

```markdown
## Bug Archived

**Bug:** <name>
**Ended:** <the Fixed by line>
**Needed a change:** <No | Yes — the change, and that it is archived>
**Archived to:** openspec/bugs/archive/<target-name>/

Fix tasks complete. All report sections resolved.

The board is not updated yet — run `scripts/sync-project-board.py` to move the
card to Done and close the issue.
```

**Output On Success With Warnings**

```markdown
## Bug Archived (with warnings)

**Bug:** <name>
**Archived to:** openspec/bugs/archive/<target-name>/

**Warnings:**
- Archived with `Fixed by` still pending
- Archived while `<change-name>` is still active
- Archived with 2 incomplete fix tasks
- `Root cause` was never investigated

Review the archive if this was not intentional.

The board is not updated yet — run `scripts/sync-project-board.py`.
```

**Output On Error (Archive Exists)**

```markdown
## Archive Failed

**Bug:** <name>
**Target:** openspec/bugs/archive/<target-name>/

Target archive directory already exists.

**Options:**
1. Rename the existing archive
2. Delete the existing archive if it's a duplicate
3. Wait until a different date to archive
```

**Guardrails**
- Announce the selected bug; prompt for selection when it is ambiguous
- Never call the OpenSpec CLI — it does not know this record exists
- Warn and confirm; never hard-block on a gate. The one hard failure is a
  target collision, which would destroy an existing record
- Preserve `.openspec.yaml` when moving to archive (it moves with the directory)
- Never edit `report.md` to satisfy a gate. A gate that fails is a fact about
  the record, and rewriting the record to pass it is falsifying the history the
  report exists to keep
- Do not run the board sync as part of this workflow; report that it is pending

**Why this exists**

`/opsx:archive` resolves its target with `openspec status --change`, and the
OpenSpec CLI enumerates `openspec/changes/` only. A bug returns
*"Change '<name>' not found"*, so the workflow never gets a `changeRoot` and has
nothing to move.

Its steps would not fit a bug anyway. Steps 2 through 4 there — the artifact
graph, `tasks.md`, and the delta-spec sync — all consume the JSON that call
returns, and a bug has no artifact graph and no delta specs. Only the final
`mv` is shared. What replaces the sync assessment is step 4 above: a bug whose
fix lives in a change waits for that change to archive.

See `openspec/bugs/README.md` for why a bug is not a change, and
`docs/project-board.md` for how both project onto the board.
